# Ourworld shared globe

`npm run build -w @ourworld/globe` produces `dist/index.html` and self-contained `assets/`. All geographic data and scripts are bundled, with no runtime CDN. The root build copies this directory to `/globe/` and native app resources.

Bridge v1: receive commands through `window.OurworldGlobe.receive(command)` or a same-origin parent `postMessage`. Events are posted to the parent, `AndroidBridge.postMessage(JSON.stringify(event))`, and `webkit.messageHandlers.ourworldGlobe.postMessage(event)` when available.

Commands: `setMarkers {places:Place[],favoriteIds:string[]}`, `focusPlace {place:Place}`, `restoreCamera {lat,lng,altitude}`, `setActive {active:boolean}`, `setTheme {theme:string}`. Events: `rendererReady`, `placeSelected {place}` (or `geoName,geoId,lat,lng` for countries without a corresponding catalog entry), `cameraChanged {lat,lng,altitude}`, `rendererError {message}`. Every envelope contains `bridgeVersion:1,event,data`.

Geographic outlines are bundled from world-atlas/Natural Earth 1:110m. 1:50m stays available in `world-atlas` if per-country coastline detail is ever required, but 110m keeps the polygon layer and bundle light with no visible difference at globe scale. `src/atlas.ts` applies the reviewed territory merges before any consumer reads the data (currently Taiwan into China, by ISO id with a name fallback); `feature()`, `geoContains()`, the land mask and the selection style all inherit the merged shape. Merged entries must not share arcs with their target. Re-run `apps/web/test/globe-boundaries.mjs` after any `world-atlas` upgrade. Basemap data is display data, not an administrative-boundary certification. Maintain reviewed local source data for a production geography release. The land mask is generated from those outlines locally; the only shipped imagery is `textures/earth-day.jpg`, no remote imagery is loaded.
