# 系统设计

## 分层与责任

网关提供同源网页、API与WebSocket。模块化单体API可多实例运行；worker独立处理异步任务。PostgreSQL是用户、消息、Profile和行程事实来源；Redis负责快照缓存、限流、消息广播和队列。S3保存文件，SMTP发送验证与找回邮件。

三端共用API、设计tokens、Profile布局及地球桥接。仅地球嵌入WebView；业务UI原生实现。地球不会读取登录令牌，资源离线打包，相机状态独立保存；后台暂停渲染。

## 页面与交互

1. 地球：启动时显示夜幕卫星地球、简洁搜索框和底部三个导航图标，不叠加标题或说明文字。四张公开纹理随三端资源打包，渲染器组合地表、固定日照、静态夜灯、地形及云层，纹理加载失败会发出错误而不假报就绪；后台暂停渲染，减少动态效果偏好下停止自动旋转。搜索支持国家、城市、景点的中英文名称和别名。点选国家后展开国家图片、介绍和城市列表；选择城市后展示城市信息、收藏和当地人入口。收藏同步到账号，回到地球保留当前视角。
2. 当地人：进入城市后创建随机快照；卡片展示城市、特长和报价。右拖显示淡绿光晕，左拖显示淡红光晕，松手时达到宽度25%才提交，否则回弹。右滑创建或复用双人会话并切换下一人；左滑只跳过本轮。没有更多人时可重新开始。多城市是次级选项，可选覆盖任一城市或全部城市；更改范围开启新一轮。
3. 聊天：会话列表中区分新会话提示和未读消息数。消息以客户端生成ID提交，可重复安全重试；支持文字、图片、地点、服务、联系方式及行程卡片。断线重连后通过历史接口补齐。
4. Profile：身份与认证数据由系统展示，内容区域为双列组件。编辑可调整组件、尺寸、顺序和主题；保存为草稿后单独预览与发布。自然语言任务生成候选布局，用户应用到草稿后仍需发布；过期候选触发版本冲突。
5. 行程与评价：会话成员创建行程，对方接受后生效；修改结束时间后需要对方重新接受，过期的接受请求会被拒绝。到期、双方确认或管理员开放后允许评价，冻结时不开放，每人一次。

## 主要数据与接口

| 数据 | 持久化和约束 | 用途 |
| --- | --- | --- |
| 用户、会话凭据、邮箱令牌 | PostgreSQL；刷新凭据保存哈希并可撤销 | 登录、验证和权限 |
| 地点、收藏 | PostgreSQL；收藏按用户与城市唯一 | 搜索、地球标记和跨设备收藏 |
| Profile 草稿、发布、历史、任务 | PostgreSQL；草稿 revision 与布局 schemaVersion 分开 | 编辑、候选校验、公开展示及恢复 |
| 双人会话、消息、outbox | PostgreSQL；无序用户对唯一，消息客户端 ID 幂等，会话序号递增 | 持久历史、重试和可靠通知 |
| 服务、审核、附件、举报、审计 | PostgreSQL 元数据；对象文件存于 S3 兼容存储 | 服务展示、认证与后台处理 |
| 行程、评价 | PostgreSQL；评价按行程和参与者限制 | 结束条件与评价资格 |
| 随机流快照、限流、队列、广播 | Redis；随机快照带过期时间 | 连续不重复浏览、多实例协调和异步处理 |

请求经 Nginx 同源转发至两个 API；API 使用 PostgreSQL 保存事实，Redis 协调队列及实例间通知。邮件和主页排版分别使用独立队列，避免模型请求占满邮件处理线程。WebSocket 负责推送，HTTP 用于提交和历史同步。完整字段、鉴权和错误见 `API_CONTRACT.md` 与 `openapi.json`。

## 核心一致性

双人会话按无序用户对唯一，城市为上下文。消息clientMessageId幂等、会话内sequence有序。消息与outbox同事务保存，推送允许至少一次，客户端按ID去重。HTTP成功代表持久化成功；通知丢失通过REST补齐。已读以最大序号更新。

随机人物一轮只打乱一次，后续按快照取卡；展示前重新过滤停用、审核变化和拉黑关系。Feed过期需要重新开始，不逐页重新随机。

Profile schemaVersion为渲染协议，revision为编辑版本。公开只读取published快照。保存、候选应用和发布检查版本；Agent没有发布权限，引用资料发布时重新校验。恢复历史创建新草稿，不覆写历史。

行程先接受再计算资格。评价资格为未取消、未冻结且满足到期/双方确认/管理员开放之一；提交评价的事务内再次检查。定时任务幂等，重启后从数据库补扫到期记录。

## 权限与数据

公开地点、公开资料和已发布内容可浏览。写入操作鉴权，必要操作要求邮箱验证。套餐发布要求服务资料通过审核。草稿、候选和历史仅本人可见；会话、消息及附件仅参与人可访问。后台管理员审核必须鉴权并记录审计，举报只提供处理所需上下文。

认证文件为私有对象，不能只凭猜到文件ID访问。所有者引用、MIME类型、上传大小、外链协议与布局枚举需校验。数据库参数化查询；消息按纯文本渲染。刷新凭据可撤销；客户端原生凭据保存于系统安全存储，模型密钥仅服务端配置。

## 模型任务

输入为提示、当前布局、允许公开的数据和组件清单。输出布局必须通过schema及资源归属校验，最大一次修正。每用户单任务、全局默认并发2、执行超时90秒。UI显示真实排队、运行、完成、失败状态。不设置密钥时明确失败，手动编辑独立可用。

## 部署和恢复

数据库迁移使用一次性服务，成功后API和worker启动。开发种子幂等；正式部署需另行关闭开发种子和替换凭据。使用持久卷保存PostgreSQL、Redis及对象文件；停止容器使用 `docker compose down`，保留卷。

备份：使用 `docker compose exec -T postgres pg_dump -U ourworld -d ourworld` 将输出写入备份文件；对象存储卷一并备份。恢复必须在隔离环境验证后再替换运行环境。凭据及.env不进入版本库。

同机压测与Android模拟器错峰，报告宿主/容器资源、连接数、延迟、错误及故障恢复。生产多机编排、应用商店提交和真实支付启用不属于本地首版部署。
